# AI critique — simulated execution (SIMULATED)

The AI was useful for turning the requested flow into repeatable browser actions and for distinguishing machine evidence from human feedback, but its first execution had a consequential operational error. The database backup used a path relative to the repository even though the command ran inside the backend directory. The copy failed, yet the backend process continued and its import-time initialization reseeded the SQLite database. The AI noticed the mistake, stopped the server, and disclosed it, but could not recover the earlier uncommitted database contents. This shows that describing a preservation step is not enough: commands that can mutate state need an explicit check that the backup exists before starting the service. The first Playwright harness also navigated directly to the cart, which reloaded the React app and discarded its in-memory cart. Its text locators then failed because the interface rendered malformed Vietnamese. These were corrected by using SPA navigation and stable selectors, and the final run verified logout through token removal. The important lesson is to separate evidence types. Passing automated checkpoints says that scripted actions succeeded in this browser configuration; it cannot reveal hesitation, comprehension, trust, frustration, or a valid SUS score. The supplied names and age can label synthetic scenarios, but they cannot become real participants through documentation. AI output needs to be checked against the assignment’s integrity rules, the live application, and the actual artifacts. Human recruitment and responses remain necessary before making usability claims.
