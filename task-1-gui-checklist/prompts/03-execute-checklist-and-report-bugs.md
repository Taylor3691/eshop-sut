# Prompt 03 — Execute Checklist and Report Bugs

Execute the approved checklist in the primary Markdown document `checklist/gui-checklist.md` against the running EShop web storefront. Use `checklist/human-reviewed-checklist.md` as the review trace and keep `checklist/gui-checklist.xlsx` as the structured backup. Before execution, follow `setup_guide.md` and record the actual backend URL, frontend URL, browser/version, operating system, viewport, device/platform, date, and tester in `docs/test-execution-report.md`.

Exercise Login, Register, and both Forgot Password steps using normal, invalid, boundary, navigation, and feedback/state cases supported by FR-01, FR-02, FR-03 and IA-01–IA-04. Mark each item only `Passed` or `Failed` after observation; use temporary `Not Executed` only for items not yet run. For each failed item, record reproduction steps, expected versus actual behavior, and a screenshot under `evidence/failed-items/`. Report only verified defects using `bug-reports/BUG-REPORT-TEMPLATE.md`; create a GitHub issue only when the defect is verified and attach its evidence. Update `checklist/gui-checklist.md`, `docs/test-execution-report.md`, `docs/test-summary.md`, the backup workbook, and the AI audit log. Apply the documented GitHub title, label, and lifecycle conventions; do not close an issue before tester retest. Never store credentials, tokens, or fabricated results.
