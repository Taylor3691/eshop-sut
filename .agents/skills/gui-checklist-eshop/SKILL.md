# GUI Checklist & Cross-Platform Testing (EShop)

Use this skill to run a disciplined, step-by-step GUI checklist workflow on any EShop screen (`frontend-web`, `frontend-admin`, or `frontend-mobile`).

Follow this sequence strictly—do not skip straight to a raw checklist dump:

`Scope & Code Inspection -> IA-01..IA-04 Checklist Design (>40 items) -> AI Blind-Spot Review -> Execution & Evidence Table -> Bug Reports & Cross-Platform Matrix -> Human Review`

## Core Rules

1. **Ground truth first:** Inspect `README.md` (especially `FR-21` to `FR-24` and the screen's `FR` specs) and the actual UI source files before writing checklist items. Never invent UI elements that do not exist.
2. **Full IA coverage:** Every checklist must cover all four Interface Aspects:
   - `IA-01`: General UI standards (language consistency, typography/single `<h1>`, button color semantics, currency `₫` formatting, tab order, responsive layout)
   - `IA-02`: Forms (required `*` markers, HTML5 input types like `type="email"` and `type="password"`, validation rules, error placement above submit button, step indicators)
   - `IA-03`: Navigation (active nav highlighting, cart badge count, `"Đăng xuất"` label, breadcrumbs on subpages, back/redirect links, auth guards)
   - `IA-04`: Feedback / state (visual feedback/toast on actions, confirmation dialogs on destructive actions, loading states, friendly empty states with icons, image `alt` text)
3. **Quantity & quality threshold:** Produce **more than 40** distinct, specific, non-repetitive, testable items across the selected primary and secondary screens.
4. **Honest execution status:** Never mark items `Passed` or `Failed` from static code reading alone unless the user confirms live observation or live browser execution was performed. Default new items to `Pending` until executed against the running SUT.
5. **Failed-item evidence only:** Record root cause in `Notes` and attach screenshot paths **only** for `Failed` items.
6. **Mandatory AI Gap Review:** Highlight blind spots AI commonly misses so the human tester can add manual items and explain *why* AI missed them.
7. **Human review required:** Flag every checklist, bug draft, and gap note for student verification before final submission.

## Expected Input

Ask for or locate:
- Primary screen name & route (e.g., `Hồ sơ cá nhân (/profile)`)
- Secondary screen(s) if included (e.g., `Đăng ký (/register)`, `Quên mật khẩu (/forgot-password)`)
- Target source file(s) (e.g., `frontend-web/src/pages/Profile.jsx`, `frontend-web/src/App.jsx`)
- Relevant functional & UI requirements in `README.md`

## Workflow

### Step 1 — Inspect Spec & UI Implementation
Read the relevant `FR` sections in `README.md` and the target React / React Native component(s). Summarize:
- Screen URL/route and purpose
- Forms & input fields present
- Buttons, links, tables, badges, and navigation controls
- Async states (loading, empty, error, success feedback)

### Step 2 — Design Initial GUI Checklist (> 40 items)
Create structured items grouped or tagged by `IA-01`, `IA-02`, `IA-03`, and `IA-04` (aim for at least 10+ items per aspect or balanced coverage totaling 45–55 items across primary + secondary screens).

Use this exact Markdown table schema (compatible with direct copy/export to Excel):

```markdown
| ID | Aspect | Screen | Check Item | Expected Result (Oracle) | Requirement Ref | Origin | Status | Notes | Screenshot |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| GUI-01 | IA-01 | Profile | Kiểm tra số lượng thẻ `<h1>` trên trang | Trang có đúng 1 thẻ `<h1>` mô tả nội dung trang | FR-21 | AI | Pending | | |
```

Rules for `Origin`:
- `AI`: generated by the AI assistant during Step 2
- `Human`: added manually by the student after reviewing AI output

### Step 3 — AI Blind-Spot & Gap Review
Explicitly examine what an AI checklist generator tends to overlook on this specific UI, such as:
- **Accessibility (A11y):** Keyboard-only `Tab`/`Enter`/`Escape` flow, focus ring visibility, `label htmlFor` association, screen-reader semantics, color contrast.
- **Visual & Layout Edge Cases:** Narrow viewport / mobile overflow on tables (`<table>` horizontal scroll), long Vietnamese strings/names wrapping or truncating, browser-native `alert()` blocking UI instead of inline feedback.
- **Localization & Domain Nuances:** Mixed English/Vietnamese labels, `"Thoát"` vs `"Đăng xuất"`, `VND` vs `₫`, Vietnamese phone number prefix (`0...`).
- **Environment / Theme Conditions:** Dark mode / OS high-contrast legibility, RTL stress checks if applicable, disabled/expired token state (`401` handling), browser autofill styling.

For each human-added gap candidate, provide a template row explaining **why AI missed it** (e.g., prompt lacked mobile viewport context, model relied only on happy-path JSX without inspecting browser UX, or model overlooked WCAG contrast).

### Step 4 — Test Summary & Execution Tracking
After execution results are recorded, generate a **Test Summary** block:

```markdown
## Test Summary
- **Screens Tested:** <Primary> (+ <Secondary screens>)
- **Total Designed:** <N> (AI: <X>, Human-added: <Y>)
- **Executed:** <N>
- **Passed:** <P>
- **Failed:** <F>
- **Pass Rate:** <P/Executed %>
```

### Step 5 — Bug Reporting & Cross-Platform Matrix (Task 3)
1. For every `Failed` item, draft a bug report formatted for both Markdown and **GitHub Issues**:
   - `Bug ID`, `Title`, `Severity`, `Checklist Ref`, `Steps to Reproduce`, `Expected Result`, `Actual Result`, `Screenshot Evidence`.
2. For **Task 3 (Cross-Browser / Cross-Platform)**, generate a comparison matrix covering at least 3 platforms (e.g., `Chrome`, `Firefox`, `Safari / Android Chrome / Expo Go`):

```markdown
| Platform / Browser / OS | Screen | Result Summary | Layout / Rendering Differences | Screenshot File |
| :--- | :--- | :--- | :--- | :--- |
```

3. Always remind the tester of **both HW03 screenshot rules** before taking Task 3 screenshots:
   - Overlay username as **student email** (`§6 Task 3`)
   - Show **student ID and full name in the form** (`§11 Anti-AI-Cheat`)
   - Capture clear **browser / OS / device name + localhost URL**

## Definition of Done
- [ ] `README.md` and UI source code verified
- [ ] Checklist contains **> 40** non-repetitive items across `IA-01`..`IA-04`
- [ ] Human-added items include explicit explanations of *why AI missed them*
- [ ] Every `Failed` item has clear `Notes` and a screenshot reference (no screenshots for `Passed` items)
- [ ] Test Summary counts match table rows
- [ ] Bugs drafted for Markdown + GitHub Issues
- [ ] Cross-platform matrix and screenshot checklist prepared for Task 3
